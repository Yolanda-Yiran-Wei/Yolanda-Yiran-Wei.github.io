Project 1: Colorizing the Prokudin-Gorskii Photo Collection

Overview

Prokudin-Gorskii took photos across the Russian Empire in the early 20th century. He recorded three exposures of each scene on a glass plate using red, green, and blue filters, hoping that special projectors would be designed so people can see these photos in color. Unfortunately, his dream didn't come true. In this project, I will extract the color channels from digitized versions of these photos to colorize them.

Implementation

I split the image into B/G/R channels, and aligned them using the metric normalized cross-correlation (NCC), which is a dot product between two mean-subtracted, normalized vectors: 

vec1 = (shifted - np.mean(shifted)) / np.linalg.norm(shifted - np.mean(shifted))
vec2 = (im2 - np.mean(im2)) / np.linalg.norm(im2 - np.mean(im2))
correlation = np.sum(vec1 * vec2)

NCC produces better results than L2 because it is invariant to changes in brightness and contrast, while L2 compares the absolute differences between the two images: 

distance = np.sqrt(np.sum((shifted - im2) ** 2))

Part 1: Single-Scale Alignment (Low-Resolution)

To align the color channels across images, I implemented an algorithm that does an exhausive search over [-15, 15] pixels for the horizontal and vertical shifts. It compares the NCC score between the two images for each shift, and the shift with the highest NCC score is the one that is used to align the images.

I aligned channels g and r to b so all three channels match when I stack them together for colorization.

I also discovered that cropping edges of images helps improve the alignment result. The crop range is set to be 10% of the image height, and I cropped this amount of pixels from the top, bottom, left, and right of the image. I did this instead of set pixels so that images with larger resolution can still be cropped to a reasonable amount of pixels.

Without cropping the edges of images, the algorithm might take into account the value differences happening on the edges of each channel, and produce inaccurate alignment, as shown in the monastery image.

Part 2: Multi-Scale Pyramid Alignment (NCC)

For images with more pixels, an exhaustive search over a displacement window of [−15, 15] is not enough to find the optimal shift, but increasing the search to something like [−50, 50] would take too much time, so I implemented a pyramid approach.

For the most basic case, each image would be downsampled by a factor of 2, and the optimal shift would be computed for the downsampled image. This would give a coarse approximation of the shift. After that, the shift would be multiplied by 2 and applied to the original image. The algorithm would then determine the optimal shift for the original image (which was already shifted by the coarse approximation).

I started with a search range of [-10, 10] pixels and search level of 4, which means I would recursively downsample and shift the image 4 times, then upsample and shift the image 4 times. Most images turned out to be correctly aligned in a few seconds, and for images that didn't align well, I changed the search range and search level to get better results.

All results below use multi-scale (pyramid) NCC.
